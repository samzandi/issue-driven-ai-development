# Security Policy

## Reporting

Do not publish secrets, private project records, credentials, or sensitive logs in a public issue. Use GitHub private vulnerability reporting when available. If it is unavailable, open a minimal issue asking for a private security contact without disclosing exploit details.

## Security boundaries

This skill must preserve explicit authorization boundaries, avoid writing secrets into project memory, and avoid claiming successful GitHub actions without verifying the result.

## Supported branch

Security fixes target the default branch during pre-1.0 development.
