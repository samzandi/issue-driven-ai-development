# GitHub mapping

Use GitHub only when the repository and authorization are confirmed.

- Parent issue: project or feature outcome, compact specification, non-goals, global acceptance criteria, and child checklist.
- Child issue: one work-item contract, including dependencies and verification.
- Labels: use existing repository labels; do not create a new taxonomy without need.
- Progress comments: record material evidence, decisions, blockers, and changed scope—not routine narration.
- Pull request: link the work item and show acceptance-criterion evidence.
- Close: close only after verification succeeds and the result is integrated as required.

Before any mutation, inspect existing issue templates, contribution guidance, branches, and project conventions. Avoid duplicate issues. Do not push, merge, close, or rewrite history without the user's authorization.
